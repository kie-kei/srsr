# srsr

[English](README.md) | **Русский**

CLI на Rust для полнотекстового поиска по Markdown. Каждый вызов поиска требует **одну явно заданную коллекцию**; каждая коллекция хранится в отдельном индексе [Tantivy](https://github.com/quickwit-oss/tantivy#features). Сетевого сервера нет. Исходные файлы не изменяются.

## Быстрая установка

Нужны stable Rust с Cargo, Git и curl. Установщик собирает приложение из исходников: готовый бинарник и Rust toolchain автоматически не скачиваются. `sudo` не нужен.

```sh
curl -fsSL https://raw.githubusercontent.com/kie-kei/srsr/main/install.sh | sh
```

Запускайте удалённые скрипты только из доверенных источников; перед запуском можно изучить [install.sh](install.sh). По умолчанию Cargo устанавливает бинарник в `${CARGO_HOME:-$HOME/.cargo}/bin` — каталог должен быть в `PATH`. Повторный запуск устанавливает приложение из актуальной ветки `main`. Cargo скачивает репозиторий по HTTPS.

Либо клонируйте репозиторий и установите приложение самостоятельно:

```sh
git clone https://github.com/kie-kei/srsr.git
cd srsr
cargo install --path . --locked
```

Для запуска без установки: `cargo build --release --locked`, затем `./target/release/srsr` вместо `srsr` в примерах.

### Удаление

```sh
cargo uninstall srsr
```

Удаляется установленный через Cargo бинарник, но не Markdown-исходники, индексы коллекций или экспортированные скиллы. Используйте тот же каталог установки и окружение Cargo, что при установке. Для удаления не нужно скачивать и запускать удалённый скрипт.

## Первый поиск

```sh
srsr --data-dir ~/.local/share/srsr index --collection work ~/notes/work
srsr --data-dir ~/.local/share/srsr search --collection work 'машина OR running'
```

`--data-dir` по умолчанию `.srsr` относительно текущего каталога. `index` и `search` выводят JSON в stdout, `skill` — Markdown. Ошибки — stderr с ненулевым exit code. Идентификатор коллекции: 1–128 ASCII-букв, цифр, `-`, `_`. Поиск отсутствующей коллекции — ошибка, а не создание пустого индекса. Путь к Markdown нужен только при индексации: поиск читает сохранённый снимок.

```sh
srsr index -c personal ~/notes/personal
srsr index -c work ~/notes/work
srsr search -c personal 'база знаний'
```

Поиск `personal` никогда не объединяет результаты с `work`, даже при одинаковых именах файлов. Отдельный индекс также изолирует BM25-статистику. Это изоляция пространства поиска, **не система авторизации**: пользователь с доступом к каталогу индексов может прочитать сохранённый текст и метаданные. Не помещайте приватные индексы в общий каталог.

## Индексация и frontmatter

Сканируются `.md`/`.MD` и другие варианты регистра расширения рекурсивно, включая скрытые каталоги. Символические ссылки не обходятся; корневой каталог-симлинк не принимается. Документы без frontmatter допустимы. YAML frontmatter должен находиться в начале файла между строками `---` и быть объектом со строковыми ключами:

Пустой блок (в том числе с одними YAML-комментариями) означает пустые метаданные. Frontmatter распознаётся только при наличии закрывающей строки `---`; без неё весь файл обрабатывается как Markdown, включая начальный горизонтальный разделитель. Поэтому забытая закрывающая строка YAML также оставит предполагаемые метаданные обычным, доступным для поиска текстом. Если обе границы есть, некорректный YAML по-прежнему прерывает обновление коллекции.

```markdown
---
title: Поиск по базе знаний
tags: [Rust, поисковые системы]
status: Draft
year: 2025
rating: 4.5
published: true
owner:
  name: Alice Smith
---
# Поиск
Машины помогают искать документы. Running wolves walked through forests.
```

Строки, числа, bool, null, вложенные объекты и массивы сохраняют JSON-типы. `null` сохраняется в выдаче, но не является индексируемым значением для exists/фильтров. Даты храните строками в кавычках: `date: "2025-01-15"`. Заголовок берётся из строкового `title`, иначе из первого H1, иначе из имени файла. Markdown разбирается в текст, а не индексируется вместе с YAML: содержимое frontmatter доступно через отдельные поля метаданных. Код также участвует в поиске.

Повторный `index` синхронизирует коллекцию с **полным переданным каталогом**: добавляет новые документы, заменяет изменённые, удаляет из индекса отсутствующие. Неизменившиеся документы не переиндексируются. Возвращается отчёт со счётчиками `added`, `updated`, `deleted`, `unchanged`. Переименование файла — удаление и добавление. Передача другого каталога под тем же именем коллекции заменит её содержимое этим каталогом; исходные файлы не удаляются.

Изменения публикуются одним commit. Ошибки чтения/frontmatter отменяют обновление, оставляя прежний снимок доступным. Tantivy допускает одного writer на коллекцию; одновременно можно искать и работать с другими коллекциями. Используются mmap, многопоточный writer и штатная политика слияния сегментов Tantivy. Для проверки изменений повторите `index`: файлового watcher нет.

## Поиск

По умолчанию запрос ищет в `title`, `body` и строковых значениях `meta`. Анализатор: Unicode-токенизация, lowercase, ASCII folding (`café` → `cafe`), русский и английский Snowball-стемминг. Язык не нужно выбирать: смешанные RU/EN-документы обрабатываются одной цепочкой. Stop words не выкидываются, чтобы сохранять смысл фраз. Поиск — стемминг, не лемматизация, не перевод и не семантический поиск. Токены размером 80 байт UTF-8 и более исключаются из полнотекстового индекса.

Ранжирование — BM25; совпадения в `title` имеют boost 2. Неявные термы объединяются AND; `--any` включает OR. Явные операторы задаются прописными буквами. Оболочка не должна интерпретировать запрос — заключайте его в одинарные кавычки.

```sh
srsr search -c work 'машины документы'
srsr search -c work 'walking'                 # найдёт walked / walking
srsr search -c work 'databaze' --fuzzy 1       # опечатки, расстояние 1 или 2
srsr search -c work 'datab' --fuzzy 1 --fuzzy-prefix
srsr search -c work '(Rust OR поиск) -body:устаревший'
srsr search -c work 'title:Rust^3 OR body:Rust'
srsr search -c work 'body:"quick brown fox"'
srsr search -c work 'body:"quick brown fox"~1' # разрешить промежутки
srsr search -c work 'body:"quick bro"*'        # префикс последнего слова фразы
srsr search -c work 'body:/datab.*/'           # regex по термам индекса
srsr search -c work '*'                       # все документы коллекции
```

Fuzzy применяется к термам полнотекстовых полей `title`, `body`, `meta`, допускает перестановку соседних символов за одну правку. **По умолчанию выключен:** отсутствие `--fuzzy` эквивалентно `--fuzzy 0`. Значения 1 и 2 включают исправление опечаток; `--fuzzy-prefix` требует ненулевого расстояния. Стемминг и нормализация остаются включёнными при выключенном fuzzy. Фразы, диапазоны и regex сохраняют собственную семантику Tantivy — `--fuzzy` не превращает их в fuzzy-фразы. Regex сопоставляется со **стеммированными термами**, а не исходным текстом; это regex-синтаксис Tantivy FST, не PCRE. Префикс — нативный оператор `"слово"*`, а не произвольный shell wildcard `foo*`.

Вес заголовка и цепочка анализатора заданы в коде. Boost в запросе, например `title:Rust^3`, меняет вес отдельного условия и сочетается с boost поля. Конфигурационного файла для весов полей или параметров BM25 нет; отдельный вес точных совпадений относительно fuzzy тоже не задан.

## Метаданные: полнотекстовый поиск и точные фильтры

Один frontmatter индексируется в двух представлениях:

| Поле | Назначение | Обработка строк |
|---|---|---|
| `meta.<путь>` | Полнотекстовый поиск | RU/EN-стемминг, lowercase, folding, fuzzy при включении |
| `exact.<путь>` | Точные значения, фильтры, агрегаты | Целая строка, регистр и пробелы сохраняются |

```sh
srsr search -c work 'meta.tags:поисковая'
srsr search -c work 'meta.owner.name:alce' --fuzzy 1
srsr search -c work 'документ' --filter 'exact.status:Draft'
srsr search -c work '*' --filter 'exact.owner.name:"Alice Smith"'
srsr search -c work '*' --filter 'exact.tags:Rust'
srsr search -c work '*' --filter 'exact.year:[2020 TO 2025]'
srsr search -c work '*' --filter 'exact.rating:{3 TO 5]'
srsr search -c work '*' --filter 'exact.published:true'
srsr search -c work '*' --filter 'exact.status: IN [Draft published]'
srsr search -c work '*' --filter 'exact.owner.name:*'
srsr search -c work '*' --filter 'exact.date:[2025-01-01 TO 2025-12-31]'
srsr search -c work 'Rust' --filter 'exact.status:Draft' --filter 'exact.year:[2024 TO *]'
```

Повторные `--filter` соединяются AND и не увеличивают score. В фильтрах используется тот же строгий парсер Tantivy, но без fuzzy. Для сравнения целых строк без стемминга и нормализации регистра выбирайте `exact`, а не `meta`. Полнотекстовые условия можно сочетать с точными и в одном основном запросе. Числовые значения поддерживают числовые сравнения; `"2025"` в YAML сохраняется строкой. Однако JSON-парсер запросов Tantivy может находить и строковые, и числовые/bool-представления: кавычки в запросе не гарантируют совпадение JSON-типа. Держите тип каждого поля стабильным между документами.

Диапазон дат в `exact` — лексикографический диапазон строк: используйте одинаковый ISO-формат и часовой пояс. Массивы соответствуют запросу при совпадении любого элемента; нет семантики nested-document для корреляции полей объектов внутри массива.

Вложенность обозначается точкой: `meta.owner.name`. Для буквальной точки в YAML-ключе экранируйте её обратным слешем: `meta.build\.version:stable` (внутри одинарных shell-кавычек). Имена корневых полей `path`, `title`, `body`, `meta`, `exact` фиксированы; одноимённые ключи frontmatter остаются внутри `meta`/`exact`.

## Выдача, фасеты и статистика

```sh
srsr search -c work 'поиск' --limit 10 --offset 10 --explain
srsr search -c work '*' --facet tags --facet status --stats rating
srsr search -c work '*' --filter 'exact.year:[2024 TO *]' --facet tags --stats rating
```

Выдача содержит `total` и `hits`: `path` относительно исходного каталога, `title`, BM25 `score`, исходные `metadata` и `snippet`. Сниппет — HTML с экранированием текста и `<b>` для совпадений в body; совпадения только в метаданных, fuzzy и regex могут не подсвечиваться. `--explain` добавляет объяснение score Tantivy. `limit`: 1–1000; `offset`: 0–100000. `total` не зависит от пагинации.

`--facet` и `--stats` принимают **путь frontmatter без `exact.`**. Это нативные агрегаты Tantivy по всем совпадениям, уже с учётом фильтров, а не по текущей странице: `aggregations.facets.<путь>` содержит terms buckets, `aggregations.stats.<путь>` — count/min/max/sum/avg числовых значений. Terms возвращает top-10 buckets по стандартным настройкам Tantivy, не все уникальные значения. Для мультизначных полей статистика считает значения; фасеты показывают document count. Агрегации используют fast fields с исходными, не стеммированными значениями.

## Скилл для агента

Инструкции находятся в [skills/srsr/SKILL.md](skills/srsr/SKILL.md) и встроены в бинарник. Вывести их можно из любого каталога — исходники и индекс рядом не нужны:

```sh
srsr skill
```

Можно использовать скилл из репозитория или экспортировать установленную версию в каталог скиллов вашего агента. Для агентов, читающих проектные скиллы из `.agents/skills`:

```sh
mkdir -p .agents/skills/srsr
srsr skill > .agents/skills/srsr/SKILL.md
```

Скилл описывает выбор коллекции, RU/EN-поиск, явные повторные запросы с fuzzy, фильтры frontmatter, ссылки на источники, агрегаты и безопасную синхронизацию. Он не индексирует файлы и не устанавливается в агента автоматически, а инструкции из найденных документов не разрешают выполнять команды.

## Разработка

```sh
cargo test --locked
cargo fmt --all -- --check
cargo clippy --all-targets --locked -- -D warnings
```

Тесты проверяют RU/EN-стемминг и опечатки, точные фильтры и фильтры по типизированным значениям, фразы/slop/prefix/regex, вложенный frontmatter, Boolean/IN/exists, агрегаты, пагинацию, синхронизацию, откат при ошибке, изоляцию коллекций, пустой frontmatter и начальные Markdown-разделители.

## Границы

- Используются [поисковые возможности Tantivy 0.27](https://docs.rs/tantivy/0.27.0/tantivy/): позиции, BM25, QueryParser, fuzzy, JSON, fast fields, aggregates, snippet, explanation, инкрементальный writer, mmap и встроенное сжатие хранилища. Векторный поиск, синонимы, перевод, сетевой API и распределённость не добавлены.
- Frontmatter — YAML, не TOML/JSON-блоки. Индексируется читаемый UTF-8 Markdown, включая код и подписи ссылок; сырой HTML не рендерится, HTML-блоки и вложения не индексируются. Не обходите несколько независимых каталогов последовательными вызовами под одним именем коллекции: каждый вызов синхронизирует полную коллекцию.
- Во время синхронизации разобранные документы удерживаются в RAM до записи, чтобы ошибка разбора не публиковала неполный снимок. Для коллекций, не помещающихся в память, понадобится двухпроходная индексация. Сам индекс хранится на диске и остаётся после завершения команды или перезагрузки. Поиск использует mmap; ОС может кешировать страницы индекса в памяти.
- Схема индекса фиксирована. При несовместимой смене версии/схемы приложение отказывает в открытии; создайте индекс в новом `--data-dir` из исходных Markdown. Не удаляйте единственную копию исходников: индекс — производные, а не резервная копия.
